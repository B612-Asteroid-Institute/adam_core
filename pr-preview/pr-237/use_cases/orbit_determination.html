Orbit determination¶

Core 0.7 has four canonical orbit-determination (OD) workflows. The Python and standalone Rust entry points call the same Rust orchestration:

Canonical OD workflows¶

Workflow

Input

Configuration

Provider

Result

run_iod

Python SourceCatalog + Associations; Rust AssociatedObservations

Bound IodRunConfig

Python Propagator | None; Rust &OdPropagator

refine

Python FittedOrbits + FittedOrbitMembers + SourceCatalog; Rust MemberedOrbits

Fitted orbits, fitted members, typed failures

Python FittedOrbits + FittedOrbitMembers + SourceCatalog; Rust MemberedOrbits

Python Propagator | None; Rust &OdPropagator

Fitted orbits, fitted members, typed failures

Every Python call returns exactly (FittedOrbits, FittedOrbitMembers, OrbitDeterminationFailures). Rust returns OdBatchResult with immutable slices for those same three products and an owning into_products() conversion. A one-object request is one batch group; there are no canonical one-group aliases.

Python table contract¶

Raw IOD and OD consume these table shapes:

  • SourceCatalog (N) requires unique, non-blank id and non-null time, ra, dec, observatory_code, and catalog_id values. The configured pipeline must leave finite positive angular uncertainty. Present OD covariances are validated as dimension six before snapshots, transforms, indexing, or variance interpretation.

  • Associations (M) requires non-null detection_id and object_id. Detection IDs reference SourceCatalog.id. A detection may belong to several hypotheses, but the same (object_id, detection_id) pair may not be repeated.

Refinement and evaluation consume:

  • FittedOrbits (O) with unique, non-blank orbit_id, an exact Cartesian state and six-dimensional covariance, and complete canonical configuration, input, state, provider, and consistency provenance;

  • FittedOrbitMembers (K) with orbit_id/obs_id foreign keys, original_astrometry, used_astrometry, input_fingerprint, and membership_fingerprint for every row; and

  • the original SourceCatalog (N). Source IDs, detection metadata, epochs, observer geometry, and original astrometry must still match the persisted fingerprints.

Every input orbit needs at least one explicit member. Evaluation may receive a validated subset of those members. Old tables lacking the canonical handoff columns must be regenerated by run_iod or run_od; Core does not guess missing scientific identity.

Python: explicit one-group IOD¶

This example deliberately selects no transforms, no resource slots, and the built-in two-body provider. None is an explicit provider choice, not an omitted argument. The named Core-v1 stage values are loaded from Rust; they are not a function default.

from adam_core.observations import Associations
from adam_core.orbit_determination import (
    IodRunConfig,
    IodStageConfig,
    ObservationPipeline,
    ResourceBindings,
    run_iod,
)

one_group = Associations.from_kwargs(
    detection_id=source_catalog.id,
    object_id=["hypothesis-1"] * len(source_catalog),
)
iod_config = IodRunConfig(
    ObservationPipeline.as_supplied(),
    IodStageConfig.core_v1(),
    ResourceBindings({}),
)
propagator = None  # Explicitly select Core's built-in two-body provider.

fitted_orbits, fitted_members, failures = run_iod(
    source_catalog,
    one_group,
    propagator,
    iod_config,
)

ObservationPipeline.as_supplied() is the only manual no-transform operation. Its canonical provenance records transforms=[]. Do not pass an empty callback list, a model dictionary, or a profile name as a substitute.

Python: batch OD with the public profile¶

The public profile helper is the one intentional Python convenience that locates the installed public EFCC18 package’s exported path. It converts that location into an explicit ResourceBindings value and passes the path to Rust, which verifies the file before acquiring a provider. No canonical OD workflow performs package discovery, download, cache lookup, or fallback for OD semantic resources. Profiles never choose a propagator.

from adam_core.orbit_determination import (
    CORE_OD_V1,
    core_od_v1_resource_bindings,
    run_od,
)

config = CORE_OD_V1.bind(core_od_v1_resource_bindings())
propagator = None  # Or a propagation-only native capsule provider.

fitted_orbits, fitted_members, failures = run_od(
    source_catalog,
    associations,
    propagator,
    config,
)

Groups follow first appearance of Associations.object_id. Rows inside each group follow SourceCatalog order. Overlap is intentional:

from adam_core.observations import Associations

overlapping = Associations.from_kwargs(
    detection_id=["obs-1", "obs-2", "obs-2", "obs-3"],
    object_id=["short-arc", "short-arc", "long-arc", "long-arc"],
)
orbits, members, failures = run_od(
    source_catalog,
    overlapping,
    propagator,
    config,
)

One hypothesis may fail scientifically while a later one succeeds. Inspect the three products together: failure rows retain the original group identity and stage counters; successful membership rows state exactly which observations belong to each emitted orbit.

Python: IOD handoff and later refinement¶

run_iod persists original and used astrometry, exact variances, complete memberships, and fingerprints. Save the orbit and member tables together, then refine them without running the observation pipeline again:

from adam_core.orbit_determination import refine, run_iod

iod_orbits, iod_members, iod_failures = run_iod(
    source_catalog,
    associations,
    propagator,
    config.for_iod(),
)

refined_orbits, refined_members, refine_failures = refine(
    iod_orbits,
    iod_members,
    source_catalog,
    propagator,
    config.for_refinement(),
)

The complete composed outcome contains iod_failures plus the outputs and failures for seeds that reached refinement. Internally, fused run_od is the same composition: prepare once, run IOD, then refine accepted states on the same rows. A matching direct and composed route has equal scientific products and canonical OD provenance. If a different valid refinement configuration is chosen, composition becomes explicitly unprofiled rather than claiming the original named profile.

Python: evaluate complete groups or a member subset¶

Evaluation has its own configuration. It does not change states or reuse a full OdConfig as hidden state.

import pyarrow.compute as pc

from adam_core.orbit_determination import evaluate_orbits

selected_id = fitted_orbits.orbit_id[0].as_py()
one_orbit = fitted_orbits.apply_mask(
    pc.equal(fitted_orbits.orbit_id, selected_id)
)
selected_members = fitted_members.apply_mask(
    pc.equal(fitted_members.orbit_id, selected_id)
)

evaluated_orbits, evaluated_members, evaluation_failures = evaluate_orbits(
    one_orbit,
    selected_members,
    source_catalog,
    propagator,
    config.for_evaluation(),
)

A smaller validated subset of selected_members is also permitted. Evaluation reports residuals, solution/outlier flags, statistics, and independent evaluation-route provenance. It does not copy prior-stage backend fields as if those stages executed again.

Mutable orbit labels¶

orbit_id is mutable relational data. Immutable association identity lives in the orbit object_id/native group identity and Rust-owned fingerprints. To relabel a handoff, edit the selected FittedOrbits.orbit_id and every matching FittedOrbitMembers.orbit_id together, then call refine or evaluate_orbits:

import pyarrow as pa

old_id = fitted_orbits.orbit_id[0].as_py()
new_id = "analyst-label"
fitted_orbits = fitted_orbits.set_column(
    "orbit_id",
    pa.array(
        [new_id if value == old_id else value
         for value in fitted_orbits.orbit_id.to_pylist()],
        type=pa.large_string(),
    ),
)
fitted_members = fitted_members.set_column(
    "orbit_id",
    pa.array(
        [new_id if value == old_id else value
         for value in fitted_members.orbit_id.to_pylist()],
        type=pa.large_string(),
    ),
)

There is no rename API. Core validates the foreign keys before provider work; a partial, duplicate, blank, or dangling relabel fails atomically.

Profiles, pipelines, and resources¶

Core Rust owns complete OD configuration, profile expansion, transform order, resource validation/parsing, numerical settings, and path-free canonical configuration provenance. Python constructs immutable declarations, binds local paths, marshals typed tables, and assembles typed results.

The configuration types have separate scopes. Their constructors perform scientific validation and raise OdConfigurationError; constructors and profile binding raise OdResourceValidationError for aggregate semantic resource failures. The workflow calls receive only already-validated values, so their invocation-time exceptions are TypeError for wrong public Python types; ValueError for static input failures and provider descriptor, identity, complete-provenance-suffix, or unknown-capability validation at the Python/Core layer; and RuntimeError for ABI-v2 table-contract violations, callback statuses, malformed responses, and backend failures. Both ValueError and RuntimeError may occur during provider acquisition before any callback executes: the validation layer, not acquisition-versus-execution timing, determines the class. The complete deterministic split is enumerated below.

  • IodStageConfig is the complete search/selection/velocity/acceptance/ correction/ranging/candidate-fit declaration. It has no pipeline or resource binding.

  • IodRunConfig binds one IodStageConfig to an ordered ObservationPipeline, exact resources, and optional immutable profile identity.

  • OdConfig contains that pipeline plus IOD and RefinementRunConfig declarations. It deliberately has no implicit Default.

  • RefinementRunConfig contains the complete fit/Jacobian/covariance/ rejection declaration.

  • EvaluationConfig independently contains covariance dimension and exact prediction-fit settings.

The closed transform set is FillMissingAstrometricUncertainty, Vfc2017AstrometricUncertaintyFloor (with explicit fill_missing), Vfc2017AstrometricUncertaintyReplace, Efcc18CatalogBiasCorrection, StationBandResidualCovarianceAdjustment (explicit Add/Replace and minimum count), PerformanceWeightedCovarianceScaling, MeasuredBiasAstrometricUncertaintyFloor, and NightlyBatchDeweighting. The VFC2017 floor operates per axis and preserves the supplied RA/Dec cross term; its Python fill_missing=False default is the deliberate legacy floor-only policy and is always serialized explicitly. VFC2017 replacement sets both cross entries to exactly +0.0 because its table carries no correlation. Performance weighting scales the complete RA/Dec covariance block by max(chi2_per_obs, 1); the measured-bias policy floors each marginal sigma and preserves the cross term. Both station/band policies require an explicit minimum residual count.

Order and repetition are authoritative. Pipeline identity is ObservationPipeline.as_supplied(); composition is ObservationPipeline.ordered(...). Python callbacks, dynamically registered transforms, model dictionaries, profile-selected propagators, and resource fallback are not supported.

CORE_OD_V1 applies EFCC18 correction and nightly deweighting. It does not fill missing uncertainty. ASTEROID_INSTITUTE_OD_V1 additionally uses the semantic station/catalog uncertainty and station/band residual-covariance slots. Deployment and distribution are outside Core; callers separately provision local files and bind all semantic slots explicitly:

from pathlib import Path

from adam_core.orbit_determination import (
    ASTEROID_INSTITUTE_OD_V1,
    ResourceBindings,
)

resources = ResourceBindings(
    {
        "efcc18_catalog_bias_table": Path("/srv/od/bias.dat"),
        "station_catalog_uncertainty_table": Path("/srv/od/station.parquet"),
        "station_band_residual_covariance_table": Path(
            "/srv/od/residual-covariance.parquet"
        ),
    }
)
institute_config = ASTEROID_INSTITUTE_OD_V1.bind(resources)

Optional policies use the same path-free declarations and exact resource bindings. For example, an explicitly ordered VFC2017 floor followed by performance weighting is declared as follows (the files must match Core’s pinned content identities):

from pathlib import Path

from adam_core.orbit_determination import (
    IodStageConfig,
    OdConfig,
    ObservationPipeline,
    PerformanceWeightedCovarianceScaling,
    RefinementRunConfig,
    ResourceBindings,
    Vfc2017AstrometricUncertaintyFloor,
)

optional_resources = ResourceBindings(
    {
        "station_catalog_uncertainty_table": Path("/srv/od/station.parquet"),
        "station_band_residual_covariance_table": Path(
            "/srv/od/residual-covariance.parquet"
        ),
    }
)
pipeline = ObservationPipeline.ordered(
    [
        Vfc2017AstrometricUncertaintyFloor(fill_missing=False),
        PerformanceWeightedCovarianceScaling(minimum_residual_count=30),
    ]
)
explicit_config = OdConfig.explicit(
    observation_pipeline=pipeline,
    iod=IodStageConfig.core_v1(),
    refinement=RefinementRunConfig.core_v1(),
    resources=optional_resources,
)

Validation aggregates missing, unused, swapped, corrupt, schema, identity, and structural problems by slot before transforms, propagation, or fitting. Absolute paths are excluded from fingerprints and provenance. A named profile never falls back to another profile or to an explicit configuration.

Standalone Rust workflows¶

Standalone Rust uses typed values directly; it does not require Python, PyO3, Arrow IPC, or a capsule for the built-in provider. Both the root and module paths deliberately expose the same four implementations:

use adam_core::{run_iod, run_od, refine, evaluate_orbits};
use adam_core::od::{
    AssociatedObservations, EvaluationConfig, IodRunConfig, IodStageConfig,
    MemberedOrbits, ObservationPipeline, OdConfig, OdPropagator,
    RefinementRunConfig,
};

fn workflows(
    associated: &AssociatedObservations,
    membered: &MemberedOrbits,
) -> Result<(), Box<dyn std::error::Error>> {
    let pipeline = ObservationPipeline::as_supplied();
    let iod_stage = IodStageConfig::core_v1();
    let refinement_config = RefinementRunConfig::core_v1();
    let iod_config = IodRunConfig::explicit(
        pipeline.clone(),
        iod_stage.clone(),
    )?;
    let od_config = OdConfig::explicit(
        pipeline,
        iod_stage,
        refinement_config,
    )?;
    let evaluation_config = EvaluationConfig::core_v1();
    let provider = OdPropagator::two_body();

    let iod = run_iod(associated, &iod_config, &provider)?;
    let full = run_od(associated, &od_config, &provider)?;
    let refined = refine(membered, &refinement_config, &provider)?;
    let evaluated = evaluate_orbits(membered, &evaluation_config, &provider)?;

    let orbit_slice = iod.fitted_orbits();
    let member_slice = iod.fitted_orbit_members();
    let failure_slice = iod.failures();
    let (orbits, members, failures) = full.into_products();
    let _ = (
        orbit_slice,
        member_slice,
        failure_slice,
        orbits,
        members,
        failures,
        refined,
        evaluated,
    );
    Ok(())
}

The executable rust/adam_core/examples/od_canonical_workflows.rs creates a deterministic non-empty two-body fixture and demonstrates the complete public handoff. It constructs one and several hypotheses; preserves overlaps, first-appearance group order, and source row order; continues after a typed scientific failure; converts IOD products with to_membered_orbits; runs standalone refinement; compares direct run_od with the explicit run_iod-then-refine composition; evaluates a full group and a validated member subset; and coordinates an orbit/member orbit_id relabel. It also shows immutable product slices, into_products(), and explicit public-profile resource binding. Run it with:

cargo run -p adam_core --example od_canonical_workflows

The separate od_external_provider example compiles the exact unsafe ABI-v2 ownership/lifetime boundary and its conversion to OdPropagator without fabricating a foreign table:

cargo run -p adam_core --example od_external_provider

The guide and workflow-docstring Python snippets are exercised by the ordinary orbit-determination unit-test suite with deterministic caller-owned tables, including exact composition and post-relabel calls.

Standalone Rust OD workflows do not discover OD semantic-resource packages or paths. Bind the public profile’s semantic slot explicitly (the separate adam_core::kernel_data resolver has its own documented kernel-discovery policy):

use adam_core::od::{profiles::CORE_OD_V1, ResourceBindings, ResourceSlot};

let resources = ResourceBindings::new().bind(
    ResourceSlot::Efcc18CatalogBiasTable,
    "/absolute/path/to/bias.dat",
);
let config = CORE_OD_V1.bind(&resources)?;

rust/adam_core/examples/validate_core_od_resource.rs validates that resource without downloading, caching, or fallback.

Determinism, empty input, and failures¶

Rust parses and validates the complete batch before provider or pipeline work. Null/blank IDs, duplicate source IDs or pairs, unknown references, ambiguous members, and input orbits without members abort atomically. Groups follow first appearance and rows follow source order. Overlapping hypotheses retain their independent groups.

Empty input returns the exact three empty products and does not acquire an external provider. Errors have four boundaries:

  1. Static preflight: malformed typed configuration, resources, IDs, memberships, covariance dimensions, or persisted provenance. These fail before provider acquisition with ValueError (or TypeError for a wrong public Python type).

  2. Provider acquisition (validation-layer split): ValueError covers a non-capsule, a capsule not named adam_core.propagator.v2, or a malformed descriptor; a NativeBackend declaration/table identity mismatch; a legacy table without the complete provenance suffix; and capability bits unknown to this Core. RuntimeError covers an ABI-v2 table-contract violation: version, base size or partial suffix, alignment, reserved words, null context or callback, missing THREAD_SAFE, empty identity strings, malformed fingerprints, or an inconsistent STM capability/callback slot. Both classes can therefore arise before callback execution.

  3. Invocation-fatal callback/backend outcome: callback ERROR, PANIC, INVALID, or an unknown status; malformed responses; unsupported request capabilities; and other backend failures raise RuntimeError and return no partial products.

  4. Per-group scientific outcome: safely isolated no-solution, refinement, or evaluation failures become deterministic rows of OrbitDeterminationFailures and later groups continue.

orbit_id appears on a failure only when a state was emitted; input_orbit_id identifies a refinement/evaluation seed when no output state exists. A non-converged fit remains in FittedOrbits with success=False only when Rust retained a real best state.

Provenance¶

Canonical fitted-orbit rows record, where applicable:

  • ordered complete source/member and membership fingerprints;

  • exact orbit state/time/origin/covariance plus physical and non-gravitational-parameter identity;

  • route and complete canonical Rust configuration, including profile identity, transforms/resources, and configuration SHA-256;

  • actual IOD/refinement/evaluation provider metadata and diagnostics;

  • IOD ambiguity, alternatives, rejection count, and rejected fraction; and

  • an unkeyed consistency digest covering route, configuration, input identity, and propagated IOD metadata.

The digest detects inconsistent persisted fields; it is not authentication or a tamper-proof signature. Resource paths and Core build identity are excluded from scientific provenance. Member rows retain original and used astrometry so prepared handoffs are lossless and auditable.

Propagation-only providers and licensing¶

A Python provider contributes only the negotiated native propagation capsule. Core still owns grouping, transforms, IOD, fitting, rejection, covariance, failures, and provenance. See Native propagation-provider ABI for the ABI-v2 identity, capability, lifetime, and error contract.

The capsule boundary loads separately built extensions and does not make adam-core link to a GPL-covered provider. A standalone Rust application that directly links a GPL-covered propagation implementation creates a different distribution situation and must satisfy that provider’s license; projects should evaluate their own obligations.
