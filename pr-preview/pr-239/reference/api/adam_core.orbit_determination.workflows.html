adam_core.orbit_determination.workflows module¶

Thin Python marshalling for Rust-owned canonical batch OD workflows.

The four public workflows are ordinary callables exported from this module:

>>> names = ("run_iod", "run_od", "refine", "evaluate_orbits")
>>> all(callable(globals()[name]) for name in names)
True
adam_core.orbit_determination.workflows.run_iod(observations: SourceCatalog, associations: Associations, propagator: Propagator | None, config: IodRunConfig) → tuple[FittedOrbits, FittedOrbitMembers, OrbitDeterminationFailures][source]¶

Run canonical batch initial orbit determination (IOD).

Rust validates the complete batch, applies the bound observation pipeline once, and executes deterministic IOD per explicit association hypothesis. A one-object request uses this same batch route.

Parameters:

  • observations (SourceCatalog (N)) – Observation rows. The required non-null columns are id (unique and non-blank), time, ra, dec, observatory_code, and catalog_id. Astrometric uncertainty columns must be finite and positive after config.observation_pipeline runs. Every present covariance has dimension six before any transform is interpreted.

  • associations (Associations (M)) – Explicit memberships with non-null detection_id and object_id. Each detection ID must reference observations.id. A detection may occur in several hypotheses, but a (object_id, detection_id) pair may occur only once.

  • propagator (Propagator or None) – Propagation-only provider. None explicitly selects Core’s built-in two-body provider. Any other value must expose the negotiated native propagation capsule; it never supplies IOD, fitting, or rejection.

  • config (IodRunConfig) – Self-contained IOD configuration containing the complete IodStageConfig, ordered bound ObservationPipeline, validated resources, and optional immutable profile identity.

Returns:

  • fitted_orbits (FittedOrbits (G_success)) – One accepted state per successful group, in first-appearance group order, with complete route/configuration/provider provenance.

  • fitted_members (FittedOrbitMembers (K_success)) – Successful-group memberships in source-table order, including original and used astrometry plus input and membership fingerprints.

  • failures (OrbitDeterminationFailures (G_failure)) – Typed, deterministic per-group scientific failures. No placeholder orbit is emitted when an IOD group has no accepted state.

Raises:

  • TypeError – If a Python table, provider, or config has the wrong public type.

  • ValueError – If static batch, membership, covariance, identity, or provenance input validation fails; provider acquisition returns a non-capsule, a capsule not named adam_core.propagator.v2, or a malformed descriptor; the NativeBackend declaration and table identity differ; a legacy table lacks the complete provenance suffix; or capability bits are unknown to this Core.

  • RuntimeError – If the table violates the ABI-v2 contract (version, base size or partial provenance suffix, alignment, reserved words, null context or callback, missing THREAD_SAFE, empty identity strings, malformed fingerprints, or inconsistent STM capability/callback slot); a callback returns ERROR, PANIC, INVALID, or an unknown status; or the provider returns a malformed response, unsupported request capability, or other backend failure. No partial products are returned. Both ValueError and RuntimeError can arise during acquisition before callback execution; the validation layer, not acquisition-versus-execution timing, determines the exception class.

Notes

Static configuration/resource/ID/membership checks complete before provider acquisition. Empty input returns three typed empty tables and does not acquire the provider. Groups follow first appearance in associations; members follow source order; overlaps are preserved. Safely isolated no-solution outcomes are rows in failures and do not stop later groups. orbit_id is a mutable relational label; immutable association identity is carried by the orbit object_id/native group identity and member fingerprints.

Examples

One explicit group with a deliberate no-transform pipeline and the built-in provider (represented by None):

from adam_core.observations import Associations
from adam_core.orbit_determination import (
    IodRunConfig,
    IodStageConfig,
    ObservationPipeline,
    ResourceBindings,
    run_iod,
)

one_group = Associations.from_kwargs(
    detection_id=source_catalog.id,
    object_id=["hypothesis-1"] * len(source_catalog),
)
iod_config = IodRunConfig(
    ObservationPipeline.as_supplied(),
    IodStageConfig.core_v1(),
    ResourceBindings({}),
)
fitted_orbits, fitted_members, failures = run_iod(
    source_catalog,
    one_group,
    None,
    iod_config,
)

adam_core.orbit_determination.workflows.run_od(observations: SourceCatalog, associations: Associations, propagator: Propagator | None, config: OdConfig) → tuple[FittedOrbits, FittedOrbitMembers, OrbitDeterminationFailures][source]¶

Run canonical batch IOD followed by refinement.

This is the complete OD workflow. Rust plans each association group, validates and applies the bound pipeline once, runs IOD, and refines each accepted seed on the exact same prepared rows.

Parameters:

  • observations (SourceCatalog (N)) – Observation rows with unique non-blank id plus required time, ra, dec, observatory_code, and catalog_id columns. Uncertainty must be valid after the configured pipeline.

  • associations (Associations (M)) – Non-null detection_id/object_id membership pairs. References must be complete and unambiguous; duplicate pairs and dangling IDs are invocation-fatal. Overlapping hypotheses are allowed.

  • propagator (Propagator or None) – Explicit propagation-only provider. None selects the built-in two-body provider; another provider must expose the native capsule.

  • config (OdConfig) – Complete bound configuration: ordered pipeline and resources, IodStageConfig, RefinementRunConfig, and optional validated profile identity. Profiles must be bound before this call.

Returns:

  • fitted_orbits (FittedOrbits (G_output)) – Accepted or retained best states in deterministic group order. Each row includes success/status, exact state identity, and complete provenance.

  • fitted_members (FittedOrbitMembers (K_output)) – Member residual/selection rows in source order with lossless original and used astrometry and Rust-owned fingerprints.

  • failures (OrbitDeterminationFailures (G_failure)) – Typed isolated IOD/refinement failures in group order. A refinement failure emits a state only when Rust retained an actual best state.

Raises:

  • TypeError – If an argument does not have the documented public type.

  • ValueError – If static batch, membership, covariance, identity, or provenance input validation fails; provider acquisition returns a non-capsule, a capsule not named adam_core.propagator.v2, or a malformed descriptor; the NativeBackend declaration and table identity differ; a legacy table lacks the complete provenance suffix; or capability bits are unknown to this Core.

  • RuntimeError – If the table violates the ABI-v2 contract (version, base size or partial provenance suffix, alignment, reserved words, null context or callback, missing THREAD_SAFE, empty identity strings, malformed fingerprints, or inconsistent STM capability/callback slot); a callback returns ERROR, PANIC, INVALID, or an unknown status; or the provider returns a malformed response, unsupported request capability, or other backend failure. No partial tuple is returned. Both ValueError and RuntimeError can arise during acquisition before callback execution; the validation layer, not acquisition-versus-execution timing, determines the exception class.

Notes

Empty input returns three empty typed tables without provider acquisition. Group order is first association appearance and member order is source order. Scientific failures continue per group; static and invocation-fatal errors abort the whole call.

Conceptually, run_od(config) is run_iod(config.for_iod()) followed by refine(config.for_refinement()) with prior IOD failures carried forward. The fused route performs the observation transforms only once; the persisted handoff consumed by standalone refine prevents a second transformation. Matching direct and composed routes have equal scientific products and canonical OD provenance. Emitted orbit_id values are mutable relational labels; immutable association identity remains in the orbit object/group identity and member fingerprints.

Examples

Bind the public profile explicitly, then run a multi-hypothesis batch:

from adam_core.orbit_determination import (
    CORE_OD_V1,
    core_od_v1_resource_bindings,
    run_od,
)

config = CORE_OD_V1.bind(core_od_v1_resource_bindings())
fitted_orbits, fitted_members, failures = run_od(
    source_catalog,
    associations,
    None,
    config,
)

The tuple always has exactly these three table types, including empty and all-failed batches.

adam_core.orbit_determination.workflows.refine(orbits: FittedOrbits, members: FittedOrbitMembers, observations: SourceCatalog, propagator: Propagator | None, config: RefinementRunConfig) → tuple[FittedOrbits, FittedOrbitMembers, OrbitDeterminationFailures][source]¶

Refine explicit orbit/member groups from a canonical handoff.

Parameters:

  • orbits (FittedOrbits (O)) – Input states. orbit_id must be unique and non-blank, coordinates must contain a valid six-dimensional state/covariance, and each row must carry complete canonical IOD/OD provenance and state identity.

  • members (FittedOrbitMembers (K)) – Explicit memberships. Required non-null columns are orbit_id and obs_id; canonical refinement also requires lossless original_astrometry/used_astrometry, input_fingerprint, and membership_fingerprint for every row. Every input orbit must have at least one member.

  • observations (SourceCatalog (N)) – Current source rows. IDs, detection metadata, epochs, observer geometry, and original astrometry must match the persisted member fingerprints.

  • propagator (Propagator or None) – Explicit propagation-only provider; None selects Core’s built-in two-body implementation.

  • config (RefinementRunConfig) – Complete fit/Jacobian/covariance/rejection declaration. It contains no hidden pipeline or IOD configuration.

Returns:

  • fitted_orbits (FittedOrbits (O_output)) – Refined or explicitly retained best states in deterministic group order.

  • fitted_members (FittedOrbitMembers (K_output)) – Updated residual/selection/member products in source order.

  • failures (OrbitDeterminationFailures (O_failure)) – Typed per-orbit scientific failures. input_orbit_id identifies the seed even when no output state is emitted.

Raises:

  • TypeError – If any table or config has the wrong public type.

  • ValueError – If static membership, covariance, source-identity, or provenance input validation fails; provider acquisition returns a non-capsule, a capsule not named adam_core.propagator.v2, or a malformed descriptor; the NativeBackend declaration and table identity differ; a legacy table lacks the complete provenance suffix; or capability bits are unknown to this Core. No partial products are returned.

  • RuntimeError – If the table violates the ABI-v2 contract (version, base size or partial provenance suffix, alignment, reserved words, null context or callback, missing THREAD_SAFE, empty identity strings, malformed fingerprints, or inconsistent STM capability/callback slot); a callback returns ERROR, PANIC, INVALID, or an unknown status; or the provider returns a malformed response, unsupported request capability, or other backend failure. Both ValueError and RuntimeError can arise during acquisition before callback execution; the validation layer, not acquisition-versus-execution timing, determines the exception class.

Notes

Groups follow first appearance of orbit_id in members; members are restored to observations order. Empty input returns three typed empty tables without acquiring the provider. Safely isolated fit failures continue. The observation pipeline is not rerun: refinement consumes the persisted used astrometry created by run_iod/run_od. Static membership, covariance, source-identity, and provenance checks complete before provider acquisition.

orbit_id is mutable relational data. Relabeling is supported only by editing the orbit row and every matching member row together before this call; there is no rename helper. Fingerprints and immutable scientific identity do not depend on that presentation label.

Examples

Persist and later refine the accepted IOD products:

iod_orbits, iod_members, iod_failures = run_iod(
    source_catalog,
    associations,
    None,
    config.for_iod(),
)
refined_orbits, refined_members, refine_failures = refine(
    iod_orbits,
    iod_members,
    source_catalog,
    None,
    config.for_refinement(),
)

iod_failures remains part of the composed batch result; refine returns only outcomes for seeds that reached this stage.

adam_core.orbit_determination.workflows.evaluate_orbits(orbits: FittedOrbits, members: FittedOrbitMembers, observations: SourceCatalog, propagator: Propagator | None, config: EvaluationConfig) → tuple[FittedOrbits, FittedOrbitMembers, OrbitDeterminationFailures][source]¶

Evaluate explicit orbit/member groups without changing their states.

Parameters:

  • orbits (FittedOrbits (O)) – Input states with unique non-blank orbit_id, six-dimensional covariance, complete state fingerprint, and validated workflow provenance. Returned coordinates are the same states.

  • members (FittedOrbitMembers (K)) – Explicit pairs selected for evaluation. Required identity columns are orbit_id and obs_id; canonical original/used astrometry and input/membership fingerprints must be present. A validated subset of a prior group’s members is allowed.

  • observations (SourceCatalog (N)) – Source rows referenced by members. Their complete persisted identity must still match.

  • propagator (Propagator or None) – Explicit propagation-only provider; None selects the built-in two-body provider.

  • config (EvaluationConfig) – Independent covariance-dimension and prediction-fit configuration. Passing an OdConfig is an error; use config.for_evaluation() or construct an explicit EvaluationConfig.

Returns:

  • fitted_orbits (FittedOrbits (O_output)) – Unchanged states decorated with evaluation status, statistics, provider metadata, and evaluation-route provenance.

  • fitted_members (FittedOrbitMembers (K_output)) – Residual, solution, and outlier rows in deterministic source order.

  • failures (OrbitDeterminationFailures (O_failure)) – Typed per-orbit scientific evaluation failures.

Raises:

  • TypeError – If a table or config has the wrong public type.

  • ValueError – If static membership, covariance, source-identity, or provenance input validation fails; provider acquisition returns a non-capsule, a capsule not named adam_core.propagator.v2, or a malformed descriptor; the NativeBackend declaration and table identity differ; a legacy table lacks the complete provenance suffix; or capability bits are unknown to this Core.

  • RuntimeError – If the table violates the ABI-v2 contract (version, base size or partial provenance suffix, alignment, reserved words, null context or callback, missing THREAD_SAFE, empty identity strings, malformed fingerprints, or inconsistent STM capability/callback slot); a callback returns ERROR, PANIC, INVALID, or an unknown status; or the provider returns a malformed response, unsupported request capability, or other backend failure. Both ValueError and RuntimeError can arise during acquisition before callback execution; the validation layer, not acquisition-versus-execution timing, determines the exception class.

Notes

Static checks precede provider acquisition. Empty input returns three typed empty tables. Groups follow first member appearance and rows follow source order. Evaluation does not refit or relabel an orbit, does not reapply an observation pipeline, and records only evaluation-stage provider/config identity rather than copying prior stage backend fields. orbit_id remains a mutable relational label, but evaluation itself never changes it; callers must edit the orbit and matching member foreign keys together.

Examples

Evaluate the complete accepted handoff with an explicit stage projection:

evaluated_orbits, evaluated_members, failures = evaluate_orbits(
    fitted_orbits,
    fitted_members,
    source_catalog,
    None,
    config.for_evaluation(),
)

To evaluate a subset, pass only member rows for the chosen orbit/observation pairs while retaining their canonical fingerprint columns.
